::W02-R2-Q1 iloc slicing::
What does <code>emperors.iloc[0:5, 0:3]</code> select?{
=Rows 0 through 4, and the first 3 columns #Correct. <code>iloc</code> slices are by integer position on both axes: rows first, columns second.
~Rows 0 through 5, and columns 0 through 3 #<code>iloc</code> slicing follows the same rule as Python list slicing: the end of the range is exclusive, so <code>0:5</code> means rows 0-4 and <code>0:3</code> means columns 0-2.
~Row 0 only, columns 5 and 3 #This describes <code>emperors.iloc[0, [5, 3]]</code>, not a slice with a colon.
~The first 5 rows and all columns #The second argument (<code>0:3</code>) restricts the columns to the first three; it does not select all columns.
}

::W02-R2-Q2 Boolean filtering::
What does <code>emperors[emperors["Cause_of_Death"] == "Assassination"]</code> select?{
=Every row where the Cause_of_Death column equals "Assassination" #Correct. The inner expression builds a True/False mask; the outer brackets keep only the True rows.
~Every row except those with Cause_of_Death equal to "Assassination" #That would require the <code>\~</code> (NOT) operator in front of the mask.
~Only the first row where Cause_of_Death equals "Assassination" #Boolean filtering returns ALL matching rows, not just the first one.
~A single True/False value #<code>emperors["Cause_of_Death"] \=\= "Assassination"</code> is itself a full column of True/False values (a mask), not a single value.
}

::W02-R2-Q3 sort_values and mutation::
TRUE or FALSE: <code>emperors.sort_values("Legitimacy")</code> modifies emperors in place — the original DataFrame is changed by this call alone.{
FALSE #Correct. <code>sort_values()</code> returns a NEW, sorted DataFrame. Unless you reassign it (<code>emperors \= emperors.sort_values(...)</code>) or pass <code>inplace\=True</code>, the original emperors is unchanged.
}

::W02-R2-Q4 Dropping a column::
Which line correctly drops the "Notes" column (not a row) from emp?{
=<code>emp.drop("Notes", axis\=1)</code> #Correct. <code>axis\=1</code> means "column direction."
~<code>emp.drop("Notes", axis\=0)</code> #<code>axis\=0</code> is the row direction — this would try to drop a row labeled "Notes," not the Notes column.
~<code>emp.drop("Notes")</code> #Without specifying axis, <code>drop()</code> defaults to <code>axis\=0</code> (rows) and would look for a row labeled "Notes" instead of a column.
~<code>emp.remove("Notes")</code> #DataFrames do not have a <code>.remove()</code> method; the correct method is <code>.drop()</code>.
}

::W02-R2-Q5 Deriving a new column::
In Task 3, you added a column like this: <code>emp["Violent_Death"] \= emp["Cause_of_Death"].str.contains("Assassination|Execution|Killed|Suicide", na\=False)</code>. If a row's Cause_of_Death is missing (NaN), what value lands in Violent_Death for that row?{
=False #Correct. <code>na\=False</code> tells <code>str.contains()</code> to treat missing values as False instead of propagating NaN — that's exactly why the hint told you to include it.
~True #Missing values don't "match" any of the listed words — <code>na\=False</code> makes them False, not True.
~NaN #Without <code>na\=False</code>, a missing Cause_of_Death would produce NaN here — but the hint explicitly sets <code>na\=False</code> so this row gets False instead.
~An error #<code>str.contains()</code> doesn't raise on missing values by default; it silently returns NaN unless <code>na\=False</code> is set, which converts that NaN to False.
}

::W02-R2-Q6 Adding a new row::
Suppose <code>new_row = \{'Name': 'Attila', 'Dynasty': 'Hunnic', 'Cause_of_Death': 'Unknown'\}</code> (matching emp's columns exactly). Which line correctly adds it as a new row to emp using the current standard pandas approach?{
=<code>emp \= pd.concat([emp, pd.DataFrame([new_row])], ignore_index\=True)</code> #Correct. <code>pd.concat()</code> combines emp with a new one-row DataFrame built from the dictionary; <code>ignore_index\=True</code> renumbers the index so the new row's label doesn't collide with an existing one.
~<code>emp.append(new_row, ignore_index\=True)</code> #<code>DataFrame.append()</code> was removed in pandas 2.0 — this method no longer exists and calling it raises an AttributeError.
~<code>emp \= pd.concat([emp, new_row], ignore_index\=True)</code> #<code>pd.concat()</code> expects a list of DataFrame-like objects, not a bare dictionary; new_row needs to be wrapped as <code>pd.DataFrame([new_row])</code> first.
~<code>emp["new_row"] \= new_row</code> #Assigning to a bracketed key on a DataFrame creates a new COLUMN named "new_row", not a new row.
}
